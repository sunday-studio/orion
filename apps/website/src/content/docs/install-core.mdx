<Callout title="Where to run it.">On a server your other machines can reach: a small VPS, a home server, or a machine on your Tailscale network. It needs Docker with the Compose plugin, `curl` and `openssl`.</Callout>

## Run the setup script

Core ships as one image, run as two services that share a single volume: `orion-core` for the API, the Console and public status pages, and `orion-core-worker` for monitor checks and alert delivery. The script does the setup for you.

```sh
curl -fsSL https://raw.githubusercontent.com/sunday-studio/orion/main/deploy/scripts/setup-core.sh | bash
```

It checks Docker, creates an `orion` folder with `docker-compose.yml` and a `.env` that holds freshly generated secrets, starts both services, waits until Core is healthy and prints the Console address and your login. It never overwrites an existing `.env`.

| Option | What it does |
|---|---|
| `--public-url <url>` | The address people and servers use to reach Core, such as `https://orion.example.com`. Default: this server's IP and port. |
| `--dir <path>` | Install folder. Default `./orion`. |
| `--version <version>` | Pin the Core image, for example `0.2.1`. |
| `--port <port>` | The port on this server. Default `8999`. |

Open the printed address from your own computer. If it does not load, allow TCP port `8999` through the server's firewall or cloud security group.

## Run with Docker Compose

The script above is a shortcut for this. Use Compose directly when you want to see and own every file. It runs the two services, `orion-core` and `orion-core-worker`, on one shared volume.

<CodeTabs labels={["Run", ".env", "docker-compose.yml"]} copyLabels={["Copy commands", "Copy variables", "Copy file"]}>

```sh
mkdir orion && cd orion
curl -fsSLO https://raw.githubusercontent.com/sunday-studio/orion/main/deploy/docker-compose.yml
curl -fsSL https://raw.githubusercontent.com/sunday-studio/orion/main/deploy/.env.example -o .env
# edit .env, then:
docker compose up -d
docker compose ps
```

```sh
ORION_ADMIN_USERNAME=admin
ORION_ADMIN_PASSWORD=<12+ characters>
ORION_JWT_SECRET=<32+ characters>
ORION_PUBLIC_URL=http://<server-ip>:8999
ORION_CORE_IMAGE=ghcr.io/sunday-studio/orion-core:0.2.1
```

```yaml
#
#   cp .env.example .env        # then set ORION_ADMIN_PASSWORD and ORION_JWT_SECRET
#   docker compose up -d        # reads .env from this folder; Console on http://<server-ip>:8999
#
# Or run deploy/scripts/setup-core.sh, which creates .env with generated secrets and starts Core.
# Every setting is documented in .env.example. Data lives in the `orion-data` volume (SQLite);
# see docs/sqlite-backup-restore.md before upgrading.
name: orion

# Hardened profile: non-root user (the entrypoint starts as root only to chown an
# older root-owned volume, then drops privileges), read-only root filesystem,
# no capabilities beyond that one-time chown/drop, resource limits and a 30s grace
# period for in-flight work. Pin ORION_CORE_IMAGE to a release tag or digest in production.
x-hardened: &hardened
  read_only: true
  tmpfs:
    - /tmp
  security_opt:
    - no-new-privileges:true
  cap_drop:
    - ALL
  cap_add:
    - CHOWN
    - SETUID
    - SETGID
  stop_grace_period: 30s

services:
  orion-core:
    <<: *hardened
    image: ${ORION_CORE_IMAGE:-ghcr.io/sunday-studio/orion-core:0.2.1}
    restart: unless-stopped
    mem_limit: ${ORION_CORE_MEMORY_LIMIT:-512m}
    cpus: ${ORION_CORE_CPUS:-1.0}
    pids_limit: 256
    ports:
      - "${ORION_HTTP_PORT:-8999}:8999"
    volumes:
      - orion-data:/data
    environment:
      ORION_DATA_DIR: /data
      ORION_PORT: "8999"
      ORION_DATA_LIFECYCLE_SCHEDULER_SECONDS: ${ORION_DATA_LIFECYCLE_SCHEDULER_SECONDS:-3600}
      ORION_REQUIRE_FRONTEND_AUTH: "true"
      ORION_ADMIN_USERNAME: ${ORION_ADMIN_USERNAME:-admin}
      ORION_ADMIN_PASSWORD: ${ORION_ADMIN_PASSWORD:?set ORION_ADMIN_PASSWORD in .env (copy .env.example)}
      ORION_JWT_SECRET: ${ORION_JWT_SECRET:?set ORION_JWT_SECRET in .env (copy .env.example)}
      ORION_ALERT_ALLOW_PRIVATE_WEBHOOKS: ${ORION_ALERT_ALLOW_PRIVATE_WEBHOOKS:-false}
      # Console "Test now" runs checks inside this process, so it needs the same target policy as the Worker.
      ORION_CORE_MONITOR_ALLOW_PRIVATE_TARGETS: ${ORION_CORE_MONITOR_ALLOW_PRIVATE_TARGETS:-false}
      ORION_PLAYWRIGHT_RUNNER: ${ORION_PLAYWRIGHT_RUNNER:-}
      ORION_PUBLIC_URL: ${ORION_PUBLIC_URL:-}
      ORION_ALERT_SMTP_HOST: ${ORION_ALERT_SMTP_HOST:-}
      ORION_ALERT_SMTP_PORT: ${ORION_ALERT_SMTP_PORT:-587}
      ORION_ALERT_SMTP_USERNAME: ${ORION_ALERT_SMTP_USERNAME:-}
      ORION_ALERT_SMTP_PASSWORD: ${ORION_ALERT_SMTP_PASSWORD:-}
      ORION_ALERT_SMTP_FROM: ${ORION_ALERT_SMTP_FROM:-}
      ORION_ALERT_SMTP_TLS: ${ORION_ALERT_SMTP_TLS:-starttls}
      ORION_ALERT_EMAIL_SECRET: ${ORION_ALERT_EMAIL_SECRET:-}
      ORION_ALERT_COOLDOWN_SECONDS: ${ORION_ALERT_COOLDOWN_SECONDS:-300}
      ORION_ALERT_RECOVERY_NOTIFICATIONS: ${ORION_ALERT_RECOVERY_NOTIFICATIONS:-true}
      ORION_METRICS_TOKEN: ${ORION_METRICS_TOKEN:-}
      ORION_LOGS_QUEUE_MAX: ${ORION_LOGS_QUEUE_MAX:-50000}
      ORION_LOGS_APP_RATE_PER_SECOND: ${ORION_LOGS_APP_RATE_PER_SECOND:-1000}
      ORION_ENROLLMENT_TOKEN: ${ORION_ENROLLMENT_TOKEN:-}
      ORION_DEADMAN_URL: ${ORION_DEADMAN_URL:-}
      ORION_TRUSTED_PROXIES: ${ORION_TRUSTED_PROXIES:-}
      ORION_PUBLIC_STATUS_MAIL_ENABLED: ${ORION_PUBLIC_STATUS_MAIL_ENABLED:-false}
      ORION_PUBLIC_STATUS_MAIL_HOST: ${ORION_PUBLIC_STATUS_MAIL_HOST:-}
      ORION_PUBLIC_STATUS_MAIL_PORT: ${ORION_PUBLIC_STATUS_MAIL_PORT:-587}
      ORION_PUBLIC_STATUS_MAIL_USERNAME: ${ORION_PUBLIC_STATUS_MAIL_USERNAME:-}
      ORION_PUBLIC_STATUS_MAIL_PASSWORD: ${ORION_PUBLIC_STATUS_MAIL_PASSWORD:-}
      ORION_PUBLIC_STATUS_MAIL_FROM_EMAIL: ${ORION_PUBLIC_STATUS_MAIL_FROM_EMAIL:-}
      ORION_PUBLIC_STATUS_MAIL_FROM_NAME: ${ORION_PUBLIC_STATUS_MAIL_FROM_NAME:-Orion Status}
      ORION_PUBLIC_STATUS_MAIL_REPLY_TO: ${ORION_PUBLIC_STATUS_MAIL_REPLY_TO:-}
      ORION_PUBLIC_STATUS_URL_ORIGIN: ${ORION_PUBLIC_STATUS_URL_ORIGIN:-}
      ORION_PUBLIC_STATUS_SUBSCRIBER_SECRET: ${ORION_PUBLIC_STATUS_SUBSCRIBER_SECRET:-}
      ORION_STATUS_PAGES_CNAME_TARGET: ${ORION_STATUS_PAGES_CNAME_TARGET:-}
      ORION_SESSION_HOURS: ${ORION_SESSION_HOURS:-12}
      ORION_LOGIN_RATE_LIMIT_ATTEMPTS: ${ORION_LOGIN_RATE_LIMIT_ATTEMPTS:-5}

      ORION_ALERT_TLS_EXPIRY_DAYS: ${ORION_ALERT_TLS_EXPIRY_DAYS:-14}
      ORION_DB_LOG_LEVEL: ${ORION_DB_LOG_LEVEL:-warn}

      ORION_ALERT_SMTP_PORT: ${ORION_ALERT_SMTP_PORT:-587}
      ORION_ALERT_SMTP_USERNAME: ${ORION_ALERT_SMTP_USERNAME:-}
      ORION_ALERT_SMTP_PASSWORD: ${ORION_ALERT_SMTP_PASSWORD:-}
      ORION_ALERT_SMTP_FROM: ${ORION_ALERT_SMTP_FROM:-}
      ORION_ALERT_SMTP_TLS: ${ORION_ALERT_SMTP_TLS:-starttls}
      ORION_ALERT_EMAIL_SECRET: ${ORION_ALERT_EMAIL_SECRET:-}
      ORION_ALERT_COOLDOWN_SECONDS: ${ORION_ALERT_COOLDOWN_SECONDS:-300}
      ORION_ALERT_RECOVERY_NOTIFICATIONS: ${ORION_ALERT_RECOVERY_NOTIFICATIONS:-true}
      # The Worker serves no admin routes and needs no admin password or JWT secret.
    healthcheck:
      # Through the entrypoint so the check runs as the orion user that owns /data.
      test: ["CMD", "docker-entrypoint.sh", "./orion-core-worker", "healthcheck"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 10s

  orion-data:
```

</CodeTabs>

The `docker-compose.yml` tab is the file in the repository, [`deploy/docker-compose.yml`](https://github.com/sunday-studio/orion/blob/main/deploy/docker-compose.yml), unchanged. It runs both services read-only with dropped capabilities and resource limits, waits for Core to be healthy before starting the worker, and passes every setting through from `.env`. A trimmed copy that leaves out the worker, the secrets or the data directory will not work.

Day to day:

| Command | What it does |
|---|---|
| `docker compose ps` | Shows both services and whether they are healthy. |
| `docker compose logs -f orion-core` | Follows the Core log. Use `orion-core-worker` for the worker. |
| `docker compose restart` | Restarts both services after you change `.env`. |
| `docker compose down` | Stops them. The data stays in the `orion-data` volume. |

Only want to try Orion on one machine? The [Quickstart](/docs/quickstart/) uses a smaller sample file.

## Required settings

Authentication is on by default. Core refuses to start unless these are set.

| Variable | What it does |
|---|---|
| `ORION_ADMIN_PASSWORD` | The admin password. At least 12 characters. |
| `ORION_JWT_SECRET` | Signs sessions. At least 32 characters. |
| `ORION_ADMIN_USERNAME` | The admin username. Defaults to `admin`. |
| `ORION_PUBLIC_URL` | Set this to your server's address or domain. It is used in the install commands the Console shows, in emails and in status page links. |
| `ORION_ENROLLMENT_TOKEN` | Optional but recommended. When set, a server can only register with this value or a one-time token from the Console. |

Everything else is optional and documented in [`.env.example`](https://github.com/sunday-studio/orion/blob/main/deploy/.env.example) and the [environment reference](https://github.com/sunday-studio/orion/blob/main/docs/deployment/core-environment.md).

<Callout type="warn" title="Do not reuse a password.">Generate both secrets, for example with `openssl rand -hex 32`, and keep the `.env` file out of version control.</Callout>

## Use a domain and HTTPS

Put a reverse proxy in front of Core, point your domain at the server, set `ORION_PUBLIC_URL` to the public address and `ORION_TRUSTED_PROXIES` to the proxy's address, then run `docker compose up -d` again. A Caddy example is in [`deploy/examples/reverse-proxy`](https://github.com/sunday-studio/orion/tree/main/deploy/examples/reverse-proxy).

## Verify it is running

<Steps>
<Step title="Check both services">`docker compose ps` in the `orion` folder shows `orion-core` and `orion-core-worker` as healthy.</Step>
<Step title="Check the health endpoint">It returns a healthy status when the API and database are up.</Step>
<Step title="Sign in to the Console">Use the admin username and the password in `.env`.</Step>
</Steps>

```sh
# on the server
curl http://127.0.0.1:8999/health
```

## Upgrading

Back up first, see [Backups and restore](/docs/backups/). Then set `ORION_CORE_IMAGE` to the new version in `.env` and run `docker compose pull && docker compose up -d`. Core applies migrations when it starts and copies the database to `backups/` first, so you can roll back. Moving from a version before 0.2.0? Read the [upgrade notes](https://github.com/sunday-studio/orion/blob/main/docs/deployment/upgrade-notes-0.2.0.md): the agent is now called the Node, installed servers re-run the installer once.
